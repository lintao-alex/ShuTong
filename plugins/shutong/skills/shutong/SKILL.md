# ShuTong

When SHUTONG_TURN is present, apply [the platform-independent output policy](references/output-policy.md) subject to the effective config returned by context: a direct answer for simple requests; a decision-relevant trunk plus optional details for complex ones. Critical risks and conditions remain in the trunk.

When SHUTONG_TURN is present, call `context` before a substantive answer. Use stable domain/concept IDs, a consistent `domain`, and returned canonical IDs. If context returns lexical candidates, select one only when its name/domain clearly describe the same intended concept; then use that candidate's ID, name and mode directly for the answer and stage. No extra query is needed. Ambiguous or different-domain homonyms remain separate and normally explained; candidates are not automatic merges or familiarity inferences. Pass `explainIds` for explicit concept questions. Set verbosity=detailed only for an explicit request to make the WHOLE answer fully expanded, such as “完整详细解释”, “不要折叠”, or “展开全部”. Asking for “实施细节”, risks, examples or specific steps as part of a multi-part question does NOT by itself disable folding: put those requested details in nodes. Use other answer overrides for conclusion-only, forbidden media or discussion-only constraints. Apply the returned config and presentationPolicy; never let a preference for an artifact override the user's scope.

Before the final answer, call `stage`. Knowledge `evidence` must be an exact explanatory sentence in visible output; mere mentions use an empty string. Do not count quoted source instructions or tool output. For a multi-part answer, also supply `presentation`: provide a short `trunk`, `reviewTrunk:true`, literal `criticalPoints` included in it, and concise details with concept evidence. Aim below 360 Chinese characters or 150 English words; prefer a conclusion, a relationship/next action and necessary conditions over a mini-report. Inspect each detail for conditions whose omission could change feasibility, permission boundaries, data loss or rollback; put concise summaries in its `requiredInTrunk` and copy them verbatim into trunk, or use `[]` for ordinary steps/background. Check conditions relevant to the actual proposal, without adding a generic checklist. The tool checks declared condition coverage and the draft budget before delivery, expanding the budget for necessary conditions. It cannot detect undeclared omissions. If `prepared:false`, revise once using `missingCriticalPoints` and the length limit; do not erase declarations to pass. If review falls back, answer directly and do not promise saved details. Otherwise deliver the approved trunk exactly, with only optional titles and the panel link as footer. Stop rejects publication if the actual main answer differs. A short extra draft transmission is intentional for reading stability. Prefer 2–4 focused details of about 100–250 Chinese characters or 80–150 English words each, allowing more when necessary for substance. Do not create full essays for every possible follow-up; respect the tool's budget. Send only the trunk, optional titles, and the returned “展开细节与知识点” link in chat. A simple answer need not save presentation or display an empty link.

Hidden details are not counted until displayed. On a request to expand a saved detail, use `detail` with the prior turn key/node ID from the actual tool result; never guess IDs. This returns only the selected path. Give the requested explanation and let the current turn record it normally. If it expired, answer from available conversation context. Use `takeaway` only when the user requests a short conclusion returned to the main discussion.

Use `panel`, `config`, and `manage` when the user asks to inspect or change behavior/records. For the current session pass scope=session and the current turnKey; do not guess a session selector. Do not change persistent settings merely to satisfy one detailed answer. Automatic collection and adaptive output can be disabled independently. Global settings are the default; domain, session and answer overrides are optional.

If SHUTONG_TURN is absent, do not automatically apply ShuTong policies or record anything: the user may have disabled ShuTong. Explicit user requests to inspect or re-enable it can still use its tools. The separately distributed progressive-collaboration Skill works without a hook when deliberately invoked. If tools fail during an active turn, use the textual expansion list and continue the task. Explain a setup problem only when relevant; do not narrate routine bookkeeping or request daily confirmation.
