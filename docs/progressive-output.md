# 主干与按需详情

复杂回答先交付结论、关键步骤或关系、待决定事项，以及会改变结论的风险和条件。通常以 3–7 个简短要点为目标，次要背景、例子和实施细节放入命名节点。简单回答直接回答；明确要求完整详解时，直接展开，不强迫折叠。

## 实际入口

Codex 对话末尾提供“展开细节与知识点”链接。点击后进入本机面板：

- 回答与细节：显示已确认的回答主干，各个详情默认收起，点击标题展开。
- 知识点：查看本轮或全部记录、勾选已知、导出、查看近期变更并撤销、清空。
- 设置：解释次数阈值及独立开关。

这是独立本地页面，不是 Codex 原生消息折叠控件。主干与详情支持 Markdown 标题、强调、列表、引用、表格、代码块和网页链接。表格与长代码可横向滚动；HTML 按文字显示，图片只显示说明，不自动加载外部资源。代码不执行；受支持的 Mermaid 流程图和时序图会在隔离视图中显示，源码仍可展开。面板暂时打不开时，仍可在对话中直接要求展开某个话题。

## 计数边界

`context` 读取当前问题相关记录和有效策略；新客户端通过 `stage` 提交短主干、`reviewTrunk:true`、详情和关键句，先检查声明条件是否齐全以及主干长度。回答完成后，Stop 检查实际首层与获批主干一致，才开放详情。省略 trunk 的旧协议仍兼容，但不能提供发送前长度检查。

生成了隐藏详情不等于解释给用户看：仅检索详情不计数；页面实际展开内容后提交展示事件，才计入该节点中有证据的知识点。同一原始回答中反复展开仍只计一次。在对话里重新解释，则按当前请求正常记录。计数表示呈现过，不表示读懂、记住或掌握。

代码核对全局 `criticalPoints` 和每个详情的 `requiredInTrunk` 是否出现在主干中。后者用于声明该详情里影响可行性、权限、数据丢失或回退能力的必要条件；填简短的主干原句，无此类条件填空数组，旧节点可以省略。模型完全未声明的风险仍无法自动发现；这不是语义完整性证明。

## 数据与预算

详情最多 12 个、路径最多 4 层、整份结构最多 32000 字符。只保存本次选择呈现的主干、详情、摘要和少量元数据，不抓取完整聊天历史。临时回合 24 小时后拒绝访问，并在后续新回合启动时清理；也可在面板立即“清除暂存详情”。未发生新回合时文件不会靠后台定时器自动删除。

当前详情在回答时提前生成。折叠可降低首层阅读量，但仍消耗生成 Token；为稳定首层，新版恢复短主干草稿传输供检查；此前省略 trunk 的方式仍支持。重复规则和工具返回字段的精简仍保留，不能据此宣称总 Token 一定更少。按点击再生成属于后续优化，本版保留点击即时展示，不额外启动模型任务。

`detail` 只返回主干、父路径的节点内容、当前节点，不返回兄弟支线。`takeaway` 保存简短结论并在主线面板展示，供对话引用；尚未实现独立子任务窗口或完整聊天分支树，也不会自动创建新任务。

## 主干长度检查

新客户端提交 `reviewTrunk:true` 和短 `trunk`。普通目标为中日韩文本 420 个可读字符或英文 180 词；全局和节点声明的条件合并去重；若关键句本身较长，则至少保留关键句长度加 96 字符／48 词的空间。计数会去除空白、常见 Markdown 强调符和链接目标，只是可复算的近似阅读量，不是像素或阅读时间。

条件漏项返回 `missing-critical-points` 及 `missingCriticalPoints` 原句；超预算返回实际长度与预算。两者共用一次修订机会，不发布未通过的详情，不允许靠删除条件声明过关。第二次仍不合格则停止循环，直接给出保留关键条件的回答，按普通机制核对知识点。不会机械截断，不要求用户额外确认。

获批后只输出原主干，可附一行“可展开”目录和面板链接。Stop 会检查去除这些尾部入口后的正文与获批稿一致；若添加了额外解释或改写了主干，就不发布未匹配的详情。它无法撤回已经显示的文字，因此交付不一致会被记录，不能声称代码强制限制了宿主所有输出。

模型仍负责识别哪些条件关键；代码只能验证其提交的条件没有被删除。不要把所有背景都标作关键句来规避长度目标。用户明确要求完整详解时直接输出，不适用渐进详情和长度检查。

## 旧协议兼容

不带 reviewTrunk 的已有客户端仍可提交 trunk 并按旧的包含匹配确认；也可省略 trunk、提交至少一句关键句，由 Stop 从实际正文取得主干。普通文档链接保留。此路径适合协议兼容，但不通过新的发送前长度验收。

详情仍建议 2–4 个聚焦节点，必要内容允许更长，避免把每个潜在追问都提前写成长文。真正按点击再生成尚未实现。


## 面板显示与兼容

Markdown 在本地解析，解析依赖随插件打包，无 CDN。只允许 http/https 链接，点击后在新页面打开，不携带面板来源；相对路径、文件和执行协议不会成为可点击链接。原始 Markdown 保留在数据中，渲染结果仅用于面板，不进入知识记录或模型上下文。

旧的已确认回答无需迁移；在临时记录有效期内重新打开新版面板即可按新格式显示。新版启动时自动替换旧面板进程，已打开的旧链接可能需要从对话重新获取。原生消息折叠、代码语法高亮与公式渲染仍未实现；Mermaid 当前支持范围见下节。


## 流程图与时序图

详情中的 mermaid 围栏现在支持 `flowchart`／`graph`（TB、TD、BT、LR、RL 方向）和 `sequenceDiagram`。打开详情后本地绘制，成功后默认收起“图示源码”；原始定义保持不变，也不额外调用模型。

渲染器随插件打包，无 CDN。图示使用独立 iframe 沙箱，不带面板访问令牌，不能读取知识记录或打开链接；不加载外部图片和字体。自定义初始化配置、前置配置及独立 click 指令回退为源码，不开放交互动作。

每图最多 6000 字符、120 行，渲染器限制 100 条边；每页面最多创建 4 个图示视图（已收起但仍加载的图也占用名额），其余显示源码。语法错误、加载失败或 10 秒内未完成会保留源码提示。此超时是界面等待上限，不是操作系统级 CPU 隔离。图示高度最多 800 像素，内容较高可在内部滚动。

其他图种、公式和动态图表暂未接入。它们仍作为代码/文本可读，不影响正文或原有知识点计数。
