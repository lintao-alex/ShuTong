# Token 对比：测量与显示

## 可以显示什么

1. **实际用量**：一次运行报告的输入、输出、缓存、工具调用和耗时。不需要再跑一遍，但无法知道同一问题“没装工具时本来会用多少”。
2. **局部压缩量**：同一份输入文本过滤前后做计数，不需要第二次 LLM 调用。这只证明文本变短，不代表整轮费用减少。
3. **完整效果差异**：同题、同模型和推理档位、相同初始知识记录、独立新任务，分别开启/关闭功能运行。这需要双份推理，但可只对少量代表问题离线抽样，不必每次日常回答都运行两份。

ShuTong 会影响生成内容和工具调用，不能凭短答案的字数倒推出节省了多少 Token。默认不在每轮显示没有基线的“节省百分比”。完整卸载对照与仅关 enabled 开关不同，必须注明。

## 社区做法

- [RTK](https://github.com/rtk-ai/rtk/blob/develop/docs/guide/resources/savings-explained.md)记录命令输出过滤前后大小，并以 bytes/4 估算 Token；官方明确该指标是命令输出压缩量，不是整轮账单比例。
- [Promptfoo](https://www.promptfoo.dev/docs/configuration/outputs/)将测试结果导出为表格/HTML，包含质量结果、Token、成本和延迟。可复用已存结果展示，新的模型运行才消耗推理额度。
- [Aider](https://aider.chat/docs/leaderboards/notes.html)把任务完成率与运行成本一起报告，并注明价格对应测试时点。只追求更少 Token 可能牺牲任务结果。
- [OpenAI Docs：非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)说明 codex exec 的 JSONL 事件，turn.completed 包含 usage。现有脚本使用这一完成事件；缓存输入和推理输出作为分项展示，不再次加到输入/输出上。

这些是各项目公开方法，不是所有社区工具都采用同一口径。模型 Tokenizer 离线计数是文本估计；API/CLI 报告的 usage 是运行用量；按公开价格换算的金额也不等于订阅实际扣费。

## 零额外模型调用的报告

```sh
node scripts/report-cost.mjs examples/token-comparison.json /tmp/shutong-token-report.html
```

示例包含 2026-09-26 的两个历史实验：功能开关 1 对、主干检查升级 4 对。前者均安装着插件，后者均开启功能；报告明确区分。它们不是当前版本基准。样本较少，不能推导普遍收益。

报告仅读取给定 JSON；不联网、不读取聊天历史、不启动 Codex。数据文件保存条件说明、配对 ID 和各侧 usage；逐次数据可以展开，缺失耗时显示“未记录”，不会伪装为零。新数据可用同一格式生成新报告。

## 以后需要新测试时

单独测试对话，先用 2 个代表问题各测 1 对（共 4 次模型运行），设置固定模型/推理档位和运行上限。保留失败、重试、工具开销和缓存分项，不为挑选好结果反复跑题。跨问题波动大时再决定是否扩样，不默认自动加量。

阅读体验由用户反馈；必要条件遗漏不作为本轮继续堆功能的阻断。保留显式完整版、追问与现有校验，Token 对比属于可选开发验收，不增加用户日常操作。
